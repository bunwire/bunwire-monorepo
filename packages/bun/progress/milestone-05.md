## Expected Behavior

After this milestone, Controllers can return native responses, JSON values, void, redirects, or application-resolved values. Later Bun HTTP features can raise framework exceptions without owning global response rendering, and applications can replace the central reporting/rendering behavior at the composition root.

## Not Expected Yet

- Form Request parsing/validation execution, sessions, CSRF middleware, authentication, pages, or file/stream response implementations.

## Important Decisions

- HTTP customization is explicit through `BunAdapter` HTTP options rather than process globals or new Core APIs.
- Production mode is the default and does not inspect `NODE_ENV`.
- `undefined` produces 204; all strictly JSON-compatible values, including primitives and `null`, produce JSON responses.
- Controller terminal results normalize before middleware unwinds; middleware short circuits and replacements receive the same final boundary.
- Known errors have stable public status classes; validation uses a stable 422 JSON shape ready for Milestone 6 integration.
- CSRF mismatch uses the framework's documented Laravel-style 419 status.
- Native 404/405 contexts expose request/server without inventing a managed route scope; managed failures additionally expose the active frozen HTTP context.

## Known Limitations

- The validation exception is an integration contract only until Milestone 6 provides Form Requests.
- Page, file, and stream response implementations remain deferred even though the resolver extension point now exists.
